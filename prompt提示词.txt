【改动前强制自检清单】

在给出任何代码改动之前，请先逐条自检并明确说明：

1. 控制流闭合：每个 if 分支是否都有对应的 else / return / continue / 抛异常？如果分支执行完后会继续往下走，必须确认后面的代码在当前条件下不会 NPE、越界、或者逻辑错误。
2. Null 传播路径：新引入或修改的每个变量，从赋值点出发，遍历所有读取点，确认每一处都不会读到 null（或读到时已有防御）。特别是 Map.get()、DAO 返回值、集合元素、外部传入对象。
3. 集合遍历中修改：循环里如果对正在遍历的集合做了 add/remove，必须用快照或迭代器，或证明新增/删除的元素不会影响当前循环。
4. 边界与格式：split / substring / startsWith / parseXxx / 数组下标，是否有越界或格式不符的可能？用 arr.length > 1 而不是 arr.length > 0 这类防御是否到位？
5. 分支互斥性：多个 if 之间是"互斥"还是"顺序可能都命中"？是否符合原意？
6. 与原逻辑一致性：改动是否只动了目标行为，没有顺手改动原有正常逻辑？如果动了，必须显式列出并解释。
