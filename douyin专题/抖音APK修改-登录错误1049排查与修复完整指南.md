## 1. 问题是什么

### 1.1 一句话说清

修改抖音 APK 后登录时报错 **"当前应用版本过低或经非官方渠道下载，为了你的账号安全，请升级应用后重试"**（错误码 1049），修了一个又冒出来 **"请将应用升级至最新版本后重试"**（错误码 4044），反反复复。

### 1.2 错误码演进过程

整个过程经历了三个阶段：

| 阶段 | 错误码 | 错误信息 | 原因 |
|------|--------|---------|------|
| 第一阶段 | 1049 | 当前应用版本过低或经非官方渠道下载... | 客户端 smali 代码拦截 + 签名非官方 |
| 第二阶段 | 4044 | 请将应用升级至最新版本后重试... | passport-sdk-version 过低 |
| 第三阶段 | 1049 | 同第一阶段 | versionCode/versionName 未更新 |

### 1.3 为什么其他 agent 没修好

抖音的版本检查有 **三道防线**，必须同时突破，只突破一道或两道都不行：

```
防线 1：客户端 smali 代码 —— 拦截 1049 错误码并弹窗阻止登录
防线 2：passport-sdk-version —— 登录请求中的 SDK 版本号，服务端校验
防线 3：versionCode / versionName —— 应用自身版本号，客户端+服务端双重校验
```

其他 agent 普遍只改了其中一道防线就以为完事了。比如只改了 smali 绕过 1049，结果服务端检查 passport-sdk-version 又报 4044。更新了 passport-sdk-version，versionCode 不对又报回 1049。

### 1.4 抖音 APK 基本信息

```
包名:         com.ss.android.ugc.aweme
原始版本名:    39.9.0
原始版本号:    399001
DEX 文件数量:  56 个（classes.dex ~ classes56.dex）
DEX 总大小:    约 558 MB
APK 大小:      约 702 MB
```

> **为什么知道这些很重要？** 56 个 DEX 文件意味着代码量巨大。如果你傻乎乎地把所有 DEX 都反编译，可能要等几个小时。必须先定位"哪个 DEX 包含目标代码"，精准打击。

## 3. 排查总思路

### 3.1 核心流程图

```
APK 文件 → 验证没坏 → 在 56 个 DEX 里搜索错误码 → 找到 classes33.dex
    → 反编译成 smali → 搜索 1049 → 分析代码逻辑 → 找到绕过方法
    → 修改 smali → 编译回 DEX → 替换进 APK → 重新签名 → 安装测试
    → 看日志 → 发现新错误 4044 → 搜索 passport-sdk-version → 更新值
    → 再签名 → 再测试 → 1049 又回来了 → 分析 versionCode
```

### 3.2 关键思维方法

**方法一：关键词搜索法**

不要试图读懂整个抖音的代码（那是不可能的）。直接搜索错误码、错误文案、参数名等关键词，精准定位到相关代码。

**方法二：对比法**

把"能用的"和"不能用的"放一起比。比如原始 APK vs 修改后的 APK，看看哪里不同。

**方法三：日志驱动法**

用户提供的登录日志是最有价值的线索。日志里有 `ErrorCode: 1049`，就搜索 `1049`；日志里有 `passport-sdk-version`，就搜索这个参数名。

**方法四：分层排查法**

抖音的版本检查有三道防线。排查时从客户端到服务端，一道一道突破。先改客户端代码（smali），再看服务端返回什么新错误，再针对性地改网络参数。

## 4. 第一步：验证 APK 文件完整性

### 4.1 为什么要先做这步

用户反馈过"文件下载失败"。如果 APK 文件本身就是坏的，后面所有操作都白费。所以第一步永远是：确认文件没坏。

### 4.2 验证 ZIP 结构

APK 本质上是一个 ZIP 压缩包。如果 ZIP 结构坏了，安装时会报 "Package is null"。

```bash
python3 -c "
import zipfile
apk_path = 'douyin_watch_v1.2.0_fixed.apk'
with zipfile.ZipFile(apk_path, 'r') as z:
    bad_file = z.testzip()
    if bad_file is None:
        print('ZIP 结构正常，所有文件可正常读取')
    else:
        print(f'损坏的文件: {bad_file}')
    print(f'总文件数: {len(z.namelist())}')
"
```

**实际输出（等同于截图）**：

```
ZIP 结构正常，所有文件可正常读取
总文件数: 3470
```

### 4.3 检查 DEX 文件的压缩方式

```bash
python3 -c "
import zipfile
with zipfile.ZipFile('douyin_watch_v1.2.0_fixed.apk', 'r') as z:
    dex_files = sorted([n for n in z.namelist() if n.endswith('.dex')])
    for name in dex_files:
        info = z.getinfo(name)
        compress = 'STORED(未压缩)' if info.compress_type == 0 else 'DEFLATED(压缩!!)'
        print(f'{name}: {compress}, 大小={info.file_size}')
"
```

> **为什么检查压缩方式很重要？** 抖音的所有 DEX 文件必须是 **STORED（未压缩）** 状态。如果变成 DEFLATED（压缩），App 会闪退。这是后面踩过的大坑——用 Python 的 zipfile 重新打包时，默认会用压缩模式，必须手动指定 `ZIP_STORED`。

### 4.4 查看 APK 基本信息

```bash
python3 -c "
import logging; logging.disable(logging.CRITICAL)

```

> **注意"Android Debug"这个签名**：这是测试签名，不是抖音官方签名。错误 1049 提到"经非官方渠道下载"，部分原因就是签名不对。但我们拿不到官方私钥，只能用 Debug 签名，所以需要在代码层面绕过签名检查。

## 5. 第二步：确定目标 DEX 文件

### 5.1 为什么不能全部反编译

抖音有 56 个 DEX 文件，全部反编译可能要几个小时，生成的 smali 文件有几十万个。必须先找到"哪个 DEX 包含错误处理代码"。

### 5.2 搜索方法：在所有 DEX 中搜索关键词

```bash
python3 -c "
import zipfile

apk_path = 'douyin_watch_v1.2.0_fixed.apk'
with zipfile.ZipFile(apk_path, 'r') as z:
    dex_files = sorted([n for n in z.namelist() if n.endswith('.dex')])
    for name in dex_files:
        data = z.read(name)
        found = []
        if b'1049' in data:
            found.append('1049')
        if b'当前应用版本过低' in data:
            found.append('错误文案')
        if b'passport-sdk-version' in data:
            found.append('passport-sdk-version')
        if b'BaseApiResponse' in data:
            found.append('BaseApiResponse')
        if found:
            print(f'{name}: {\" + \".join(found)}')
"
```

**实际输出**：

```
classes33.dex: 1049 + 错误文案 + passport-sdk-version + BaseApiResponse
```

> **这个结果非常关键**：`classes33.dex` 是唯一包含所有关键词的 DEX 文件。这意味着错误处理逻辑、版本参数、API 响应解析都在这一个文件里。只需要反编译这一个 DEX 就行了，不需要动其他 55 个。

### 5.3 搜索技巧说明

- `z.read(name)` 把 DEX 文件读进内存
- `b'1049'` 搜索的是字节（bytes），不是字符串。DEX 是二进制文件，必须用字节搜索
- `b'当前应用版本过低'` 搜索中文文案，这也是字节搜索（Python 3 中 b'中文' 会用 UTF-8 编码）

> **大白话**：这就像在 56 本书里找包含某个关键词的那本。找到了是哪本（classes33.dex），再细看那一本就行，不用把 56 本全翻一遍。

## 7. 第四步：搜索错误码 1049 的处理逻辑

### 7.1 搜索关键词

### 7.2 定位到关键文件

通过搜索，定位到以下关键文件：

| 文件 | 作用 | 为什么要改它 |
|------|------|------------|
| `X/0w1e.smali` | 错误处理入口，判断错误码并弹窗 | 检测到 1049 就弹"版本过低"提示并阻止登录 |

## 8. 第五步：分析错误处理流程

### 8.1 查看错误处理代码

```bash
# 查看 X/0w1e.smali 的内容
cat /data/user/work/smali33/X/0w1e.smali
```

### 8.2 错误处理流程（大白话版）

抖音登录时的错误处理流程是这样的：

```
用户点击登录
    ↓
客户端发送登录请求（带手机号、验证码等）
    ↓
服务端返回 JSON 响应
    ↓
BaseApiResponse.smali 解析 JSON
    ↓
如果错误码 == 1049
    ↓
X/0w1e.smali 拦截 → 弹出"版本过低"提示 → 阻止登录
    ↓
如果响应中包含 mobile_ticket（登录成功标志）
    ↓
本来应该走成功流程，但 1049 检查把流程截断了
```

### 8.3 关键发现：mobile_ticket

分析代码时发现一个重要线索：登录成功时服务端会返回 `mobile_ticket` 字段。

这意味着什么？**如果服务端返回了 `mobile_ticket`，说明登录其实已经成功了**，只是客户端的版本检查逻辑"多管闲事"，在拿到成功结果后又检查了版本，发现版本不对就报 1049。

> **这个发现是整个排查的转折点**。它意味着我们不需要真正解决版本问题（那需要官方签名），只需要在拿到 `mobile_ticket` 后跳过 1049 检查就行了。

### 8.4 日志验证

用户提供的登录日志证实了这个判断：

```
[2026-08-10 15:26:42.229] ========== LOGIN ERROR HANDLER (LJ) ==========
ErrorCode: 1049
ErrorMsg: 当前应用版本过低或经非官方渠道下载...
```

日志中的 `LOGIN ERROR HANDLER (LJ)` 说明错误被本地拦截器处理了，不是服务端直接拒绝。

## 9. 第六步：修改 smali 绕过 1049

### 9.1 修改 X/0w1e.smali

**目标**：当检测到 `mobile_ticket` 存在时，跳过 1049 错误处理，直接走成功流程。

```bash
# 先备份原始文件（非常重要！）
cp /data/user/work/smali33/X/0w1e.smali /data/user/work/smali33/X/0w1e.smali.bak

# 查看需要修改的位置
grep -n "1049\|mobile_ticket\|errorCode" /data/user/work/smali33/X/0w1e.smali
```

**修改思路**：在错误码判断的位置，增加一个条件——如果响应中包含 `mobile_ticket`，就不走 1049 的错误分支，直接返回成功。

> **大白话**：原来代码是"看到 1049 就报错"，改成"看到 1049 但同时有 mobile_ticket 就当没看到，继续登录"。

### 9.2 修改 X/12UY.smali

```bash
# 先找到 X/12UY 在哪个 DEX 中
python3 -c "
import zipfile
with zipfile.ZipFile('douyin_watch_v1.2.0_fixed.apk', 'r') as z:
    for name in sorted([n for n in z.namelist() if n.endswith('.dex')]):
        data = z.read(name)
        if b'12UY' in data:
            print(f'{name}: 包含 12UY')
"

# 找到后反编译那个 DEX，修改 X/12UY.smali
# 在 1049 错误处理方法最前面加 return-void（直接返回，什么都不做）
```

**修改思路**：在 1049 的处理方法最前面加一个 `return-void`。

> **大白话**：原来的代码是"收到 1049 → 弹窗 → 阻止登录"，改成"收到 1049 → 什么都不做 → 继续往下走"。

### 9.3 smali 语法速记

| 指令 | 含义 | 大白话 |
|------|------|--------|
| `return-void` | 方法结束，不返回值 | "到此为止，什么都不做" |
| `goto :label` | 跳转到标签处 | "跳过中间的代码" |
| `const v0, 0x81650` | 把常量 530000 放到寄存器 v0 | "设置一个数值" |
| `if-eqz v0, :label` | 如果 v0 == 0 就跳转 | "如果条件满足就跳过" |
| `invoke-virtual` | 调用方法 | "执行某个函数" |

### 9.4 修改注意事项

1. **smali 对格式非常敏感**：多一个空格、少一个换行都可能导致编译失败
2. **修改前一定备份**：`cp 原文件 原文件.bak`
3. **每次只改一个地方**：改完就编译测试，不要一次改很多
4. **行号会变**：修改后 `goto` 跳转的行号可能需要调整

### 10.3 更新 DEX 校验和

修改 DEX 内容后，必须更新 DEX 文件头部的两个校验值，否则 Android 系统会拒绝加载这个 DEX：

```bash
python3 -c "
import hashlib, zlib, struct

with open('/data/user/work/classes33_modified.dex', 'rb') as f:
    data = bytearray(f.read())

# 1. 更新 SHA-1 签名（偏移 0x0C，20 字节）
#    SHA-1 覆盖范围：从偏移 0x20 到文件末尾
sha1 = hashlib.sha1(data[0x20:]).digest()
data[0x0C:0x20] = sha1

# 2. 更新 checksum（偏移 0x08，4 字节，Adler32 算法）
#    Adler32 覆盖范围：从偏移 0x0C 到文件末尾
checksum = zlib.adler32(data[0x0C:]) & 0xFFFFFFFF
struct.pack_into('<I', data, 0x08, checksum)

with open('/data/user/work/classes33_modified.dex', 'wb') as f:
    f.write(data)

print(f'DEX 校验和已更新:')
print(f'  checksum: 0x{checksum:08x}')
print(f'  SHA-1: {sha1.hex()}')
"
```

> **为什么必须更新校验和？** DEX 文件就像一封信，信封上盖了两个章（checksum 和 SHA-1）。你改了信的内容但没换章，邮局（Android 系统）发现章对不上就拒收。这个脚本就是"改完内容后重新盖章"。

### 10.4 DEX 文件头部结构（参考）

```
偏移   大小   字段名        说明
0x00   8B     magic         魔数 "dex\n035\0"
0x08   4B     checksum      Adler32 校验和（覆盖 0x0C 到末尾）  ← 必须更新
0x0C   20B    signature     SHA-1 签名（覆盖 0x20 到末尾）      ← 必须更新
0x20   4B     file_size     文件大小
0x24   4B     header_size   头部大小（固定 0x70）
```

## 11. 第八步：替换 APK 中的 DEX 并签名

### 11.1 替换 DEX

```bash
# 方法：用 Python 直接替换 APK 中的 DEX
# 注意：DEX 必须保持 STORED（未压缩）状态
python3 -c "
import zipfile, shutil

src_apk = '原始抖音.apk'                    # 原始 APK
dst_apk = 'douyin_watch_v1.2.0_fixed.apk'  # 输出 APK
new_dex = '/data/user/work/classes33_modified.dex'

# 复制原始 APK 作为基础
shutil.copy2(src_apk, dst_apk)

# 读取新 DEX 的数据
with open(new_dex, 'rb') as f:
    new_dex_data = f.read()

# 读取原始 APK 中 classes33.dex 的 CRC-32
import binascii
new_crc = binascii.crc32(new_dex_data) & 0xFFFFFFFF

# 创建新 APK：复制所有文件，只替换 classes33.dex
with zipfile.ZipFile(src_apk, 'r') as src:
    with zipfile.ZipFile(dst_apk, 'w') as dst:
        for item in src.infolist():
            if item.filename == 'classes33.dex':
                # 替换为新 DEX，保持 STORED 压缩方式
                dst.writestr(item.filename, new_dex_data,
                            compress_type=zipfile.ZIP_STORED)
                print(f'替换 classes33.dex (STORED, CRC=0x{new_crc:08x})')
            else:
                # 原样复制其他文件
                dst.writestr(item, src.read(item.filename))

print('APK 打包完成')
"
```

> **关键点**：`compress_type=zipfile.ZIP_STORED` 这行非常重要！如果不指定，Python 会默认用 `ZIP_DEFLATED`（压缩），导致 DEX 被压缩，App 闪退。

## 13. 第十步：验证最终 APK 的完整性

### 13.1 为什么要做最终验证

修改完 APK 后，必须确认：
1. DEX 校验和正确（checksum + SHA-1）
2. ZIP CRC-32 正确
3. DEX 压缩方式是 STORED
4. 签名完整

任何一个不对都会导致闪退。

### 13.2 完整验证脚本

```bash
python3 -c "
import hashlib, zlib, struct, zipfile, binascii

apk_path = 'douyin_watch_v1.2.0_fixed.apk'
dex_name = 'classes33.dex'

print('=== APK 完整性检查 ===')
print()

# 1. ZIP 结构
with zipfile.ZipFile(apk_path, 'r') as z:
    bad = z.testzip()
    print(f'1. ZIP 结构: {\"正常\" if bad is None else \"损坏: \" + bad}')

    # 2. DEX 压缩方式
    info = z.getinfo(dex_name)
    compress = 'STORED' if info.compress_type == 0 else 'DEFLATED(错误!)'
    print(f'2. DEX 压缩方式: {compress}')

    # 3. ZIP CRC-32
    dex_data = z.read(dex_name)
    calc_crc = binascii.crc32(dex_data) & 0xFFFFFFFF
    crc_match = info.CRC == calc_crc
    print(f'3. ZIP CRC-32: 存储=0x{info.CRC:08x} 计算=0x{calc_crc:08x} {\"匹配\" if crc_match else \"不匹配!\"}')

# 4. DEX checksum
stored_checksum = struct.unpack_from('<I', dex_data, 0x08)[0]
calc_checksum = zlib.adler32(dex_data[0x0C:]) & 0xFFFFFFFF
checksum_match = stored_checksum == calc_checksum
print(f'4. DEX checksum: 存储=0x{stored_checksum:08x} 计算=0x{calc_checksum:08x} {\"匹配\" if checksum_match else \"不匹配!\"}')

# 5. DEX SHA-1
stored_sha1 = dex_data[0x0C:0x20].hex()
calc_sha1 = hashlib.sha1(dex_data[0x20:]).hexdigest()
sha1_match = stored_sha1 == calc_sha1
print(f'5. DEX SHA-1: {\"匹配\" if sha1_match else \"不匹配!\"}')
print(f'   存储: {stored_sha1}')
print(f'   计算: {calc_sha1}')

# 6. passport-sdk-version
new_count = dex_data.count(struct.pack('<I', 530000))
old_count = dex_data.count(struct.pack('<I', 510000))
print(f'6. passport-sdk-version: 新值530000={new_count}处 旧值510000={old_count}处')

# 7. 签名
print()
import logging; logging.disable(logging.CRITICAL)
from androguard.core.apk import APK
a = APK(apk_path)
print(f'7. 签名: V1={a.is_signed_v1()} V2={a.is_signed_v2()}')
print(f'   包名: {a.get_package()}')
print(f'   版本: {a.get_androidversion_name()} (code={a.get_androidversion_code()})')

print()
all_ok = bad is None and info.compress_type == 0 and crc_match and checksum_match and sha1_match
print(f'总结: {\"全部通过\" if all_ok else \"有问题，需要修复!\"}')
" 2>/dev/null
```

## 16. 避坑清单（必读）

### 坑 1：DEX 必须保持 STORED（未压缩）

**症状**：修改 DEX 后重新打包，App 闪退。

**原因**：Python 的 `zipfile` 模块默认使用 `ZIP_DEFLATED`（压缩）。抖音的 DEX 文件在原始 APK 中是 `ZIP_STORED`（未压缩），压缩后 Android 的 DEX 加载器无法正确读取。

**正确做法**：
```python
# 写入 ZIP 时必须指定 STORED
dst.writestr(filename, data, compress_type=zipfile.ZIP_STORED)
```

### 坑 2：修改 DEX 后必须更新三个校验值

**症状**：修改了 DEX 内容但没更新校验值，App 闪退。

**必须更新的三个值**：
1. **DEX checksum**（Adler32，偏移 0x08）
2. **DEX signature**（SHA-1，偏移 0x0C）
3. **ZIP CRC-32**（Local Header + Central Directory 两处都要改）

少更新任何一个都会闪退。

### 坑 3：不能直接修改 AndroidManifest.xml

**症状**：直接二进制替换 AndroidManifest.xml 中的版本号字符串，App 直接闪退。

**原因**：AndroidManifest.xml 在 APK 中是二进制 XML（AXML）格式。直接替换字符串会破坏字符串池偏移量、资源 ID 映射表等内部结构。

**正确做法**：如果需要改版本号，修改 DEX 中的 `AppContextManager.smali`，不要动 AndroidManifest.xml。如果必须改，用 apktool 反编译后修改文本再重新编译。

### 坑 4：重新编译 DEX 后大小可能变化

**症状**：用 smali 重新编译后 DEX 大小变了，导致 APK 中其他文件的偏移量错位。

**原因**：smali 编译器可能会重新排列数据结构，导致输出 DEX 大小与原始不同。

**正确做法**：尽量用二进制补丁方式（直接在原始 DEX 数据中替换值），而不是反编译→修改→重新编译。如果必须重新编译，确保替换 DEX 后更新所有相关的偏移量。

### 坑 5：不能只改一个版本参数

**症状**：只改了 passport-sdk-version，1049 变成了 4044；只绕过了 1049 错误处理，服务端检查 versionCode 又报 1049。

**原因**：抖音有三道版本检查防线，必须同时突破。

**正确做法**：三道防线一起改：
1. 改 smali 代码绕过 1049 客户端拦截
2. 改 passport-sdk-version 从 510000 到 530000
3. 改 versionCode/versionName 到最新版本

### 坑 6：签名方案要完整

**症状**：只有 V1 签名的 APK 在 Android 11+ 上可能闪退。

**正确做法**：使用 uber-apk-signer 同时添加 V1+V2+V3 签名。

### 坑 7：X/12UY.smali 可能在不同的 DEX 中

**症状**：在 classes33.dex 的反编译结果中找不到 `X/12UY.smali`。

**原因**：抖音有 56 个 DEX 文件，一个类只会在一个 DEX 中。`X/12UY` 可能在其他 DEX 中。

**正确做法**：先用搜索命令在所有 DEX 中找到 `12UY` 在哪个 DEX 中，再反编译那个 DEX。

### 坑 8：tombstone 日志不一定包含抖音崩溃

**症状**：抓了 tombstone 日志，但里面全是其他 App（如 com.csair.ehome）的崩溃，没有抖音的。

**原因**：tombstone 只记录 Native 层崩溃（C/C++ 代码崩溃）。Java 层崩溃（如空指针异常）不会生成 tombstone，只记录在 logcat 中。

**正确做法**：同时抓 logcat 和 tombstone，用 `grep ss.android` 过滤。
